# Finite support fusion with latent confounding

This experiment validates passive CLAIM-FUSE on maximal ancestral graphs (MAGs). Graph inference uses observed variables only. The existing SMC mutation and active discovery implementation remain restricted to DAGs.

The fixed design has 20 linear Gaussian SCMs with ten observed variables, two hidden roots, and nested sample sizes of 200 and 1,000. The reference MAG must equal the latent projection of the full generating DAG. Each dataset supplies one Fisher Z FCI fit at significance 0.05. Candidate construction retains at most 200 distinct MAGs whose canonical PAG equals the FCI output. Candidates must be maximal and ancestral and must not have undirected edges. A Zhang completion and random endpoint proposals supply candidates, but passing endpoint checks alone is insufficient. Equal probability over retained candidates is an empirical approximation, not uniform sampling of an entire equivalence class.

Data-only inference and passive fusion use the same candidates. The synthetic expert supplies ten balanced claims from each of Groups I, II and III. Thirty predicate identities are shared across sample sizes and response replicates. Answers independently flip their true values with probability 0.2, and supplied confidence is 0.8. Five response seeds are shared across sample sizes. The truth is used for expert generation and evaluation only, never candidate selection or weighting before evidence.

Expected endpoint distance evaluates the full distribution. Endpoint F1 and bidirected adjacency F1 evaluate the maximum-probability graph under the existing deterministic tie rule. Paired 95% intervals resample SCM indices after averaging response replicates. Support size, completion failures, reference inclusion and minimum attainable endpoint distance are reported separately. Failure to include the reference does not invalidate a dataset or trigger insertion of an oracle candidate.

The runner is `cd_llm.experiments.latent_mag_validation`. It provides `init`, `run`, `worker` and `aggregate` actions. A run identifier is a UTC timestamp. Results are stored under workspace `results/<run-id>/latent_mag_validation`, including the manifest, observations, full/reference graphs, coefficients, claims, PAGs, candidate weights, individual responses, updated probabilities and reports. Command logs belong under workspace `out/<run-id>/latent_mag_validation`. Java 21 or newer and the pinned Tetrad package are required for equivalence certification.

The manifest fingerprints the implementation and protocol. Completed matching artifacts are reused; incompatible artifacts are rejected. The four worker indices each process five complete SCMs, including both sample sizes. Aggregation reports missing and failed datasets rather than silently replacing them. Historical MAG summaries are not reused because they were produced under an older evidence model.
